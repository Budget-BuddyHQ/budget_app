# Auth email templates

Four HTML emails for the Supabase auth flows, generated by
`tool/build_auth_emails.py`. **Nothing in the app reads these** — the mails are
sent by Supabase's servers, so they have to be pasted into the dashboard by
hand. That is exactly why they looked untouched: the default template is a bare
`<h2>` and a naked link on a white page, and it goes to the same child every
other screen in this app is careful with.

## How to install them

Supabase Dashboard → **Authentication** → **Emails** → **Templates**. For each
one, paste the file into *Message body* and set the subject:

| Template | File | Subject line |
|---|---|---|
| Reset Password | `reset_password.html` | Reset your Budget Buddy password |
| Confirm signup | `confirm_signup.html` | Confirm your Budget Buddy account |
| Magic Link | `magic_link.html` | Your Budget Buddy sign-in link |
| Change Email Address | `change_email.html` | Confirm your new Budget Buddy email |

`{{ .ConfirmationURL }}` is Supabase's own placeholder and is substituted when
the mail is sent. It appears **twice** in each file — once on the button and
once as visible text — and both must survive. If you edit these by hand rather
than regenerating, check it is still there in both places.

`reset_password.txt` is a plain-text version. Supabase's dashboard does not
take a separate text part, so it is here for whenever the project moves to a
real sending provider (Resend, Postmark, SES) — a password reset is exactly the
mail that gets opened on a locked-down work client, and an HTML-only link is a
support ticket.

## Why the markup looks ancient

Tables, inline styles, no external images, and a button wrapped in its own
one-cell table. Every one of those is a constraint rather than a preference —
Outlook renders through Word's layout engine, Gmail strips `<style>` blocks in
several contexts, and most clients block remote images until the reader asks
for them. `tool/build_auth_emails.py` explains each one at the point it applies.

The one real design decision: the body is **dark-on-light** even though the app
is a dark forest theme. Several clients force their own background, and the
dark-mode inversion in Gmail and Outlook mangles hand-set dark palettes far
more often than light ones. The header band carries the brand; the part
somebody has to actually read stays legible everywhere.

## Regenerating

```bash
python tool/build_auth_emails.py
```

Edit the copy in `TEMPLATES` at the bottom of that script, not in the HTML —
the HTML is output.
